# AGENTS.md

How to add a first-party Module. Terms follow [GLOSSARY.md](../GLOSSARY.md); the contract is in [Module contract](../docs/architecture/module-contract.md).

## Checklist

1. `registry-src/<slug>/module.ts`: the manifest. The slug matches the manifest name regex (`trigger-dev`, not `trigger.dev`).
2. `registry-src/<slug>/files/`: the plain source files, written to logical Targets, never to literal paths.
3. `registry-src/<slug>/catalog.json`: the Catalog fragment. List only dependencies missing from the latest Release Catalog; never redefine a released one. The Module is then a Pending Module ([ADR 0024](../docs/adr/0024-pending-modules-catalog-fragments-and-release-cuts.md)).
4. `registry-src/<slug>/ambient.d.ts` (optional): types for the Module's own new packages.
5. An `agents` Region appended to `AGENTS.md` (every new or bumped Module).
6. `files[]` entry `.claude/skills/<name>/SKILL.md`, only for complex Modules (`next`, `prisma`, `better-auth`, `astro`, `starlight`, `shadcn`, `trigger-dev`, `tanstack-router`, `wxt`, `tsdown`, `adr-docs`).
7. `packages/aokit/test/modules/<slug>.test.ts`: a VFS test of the default and monorepo renders, the Region, dependency placement and requires/conflicts errors.
8. `tools/real-build/curated/<slug>.json` (optional): adds a real-build job with no workflow edit.

## Rules

- Never edit `registry/`; it is generated by `registry:build`.
- Never edit another Module's directory; integrate through Extension points and Capabilities.
- Never add a Module to the existing seven-name regression lists.
- Generation is deterministic: no generated secrets, no timestamps ([ADR 0012](../docs/adr/0012-deterministic-generation-and-atomic-writes.md)).
- Files directly in `registry-src/` (this file, `ambient.d.ts`, `yanked.json`) are not Modules; `registry:build` reads only directories.
